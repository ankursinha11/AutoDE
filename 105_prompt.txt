- **Sort**: {permid}
- **Merge**: {permid}
- **Output**: Block compressed lookup file ediComGenPatientAcctsXRefPermIDJoin.idx/lkp

- **Filters**: isdeleted == 0
- **Transformation**: Encrypt PII fields (firstname, middlename, lastname) using AES encryption
- **Output**: ediGenClusteredAccts.lkp

**Step 13: Read PatientAcctCommercialHelpers**
- Purpose: Read commercial insurance helper data
- **Filters**: isdeleted == 0

**Step 14: Transform PatientAcctCommercialHelpers**
- Purpose: Create demographics hash lookup
- **Transformation**: string_to_hex(in.demographicshash) → demographicsHashString
- **Output**: Block compressed lookup file ediGenPatientAcctCommercialHelpers.idx/lkp with keys {edipartnerfk, demographicsHashString}

**Step 15: Read EdiMessages**
- Purpose: Read EDI message data with job/submitter/partner enrichment
- **Filters**: 
  - isdeleted == 0
  - generatedate > datetime_add(now(), -180) (last 180 days)
  - currentstatus in [1, 2]
- **Lookups**: Join with lkpEdiJobs, lkpEdiSubmitters, lkpEdiPartners

**Step 16: EDI Submitter Backlog Processing (Step 15a)**
- Purpose: Calculate backlog by submitter
- **Filter**: first_defined(tHospitalProviderNums.enabled, 0)
- **Sort Keys**: {edisubmitterfk, transportunit, maxunitsperday}
- **Rollup**: Sum message counts and entities
- **Output**: lkpEdiSubmitterBacklog.lkp with isBacklogFlag

**Step 17: EDI Partner Backlog Processing (Step 15b)**
- Purpose: Calculate backlog by partner
- **Filter**: first_defined(tEdiPartners.demographicqueriesallowedflag, 0) == 1
- **Sort Keys**: {edipartnerfk, transportunit, maxfilesperday}
- **Rollup**: Sum message counts and entities
- **Output**: lkpEdiPartnerBacklog.lkp with isBacklogFlag

Key filters applied: hospitalfk >= 1000 (only eligible hospitals), createdate within last 1095 days (3 years of data for historical matching), and isdeleted = 0 (exclude soft-deleted records). The GMRN serves as the primary cross-system patient identifier used in all downstream lookups. Data is read using eScan Data Reader component with both base and delta file processing."

### 3. Code Evidence Requirements
- Always include actual code snippets (5-15 lines)
- Show context (variable names, function calls, conditions)
- Format code clearly with proper line breaks
- Include cell/function location precisely

### 4. Search Strategy for Missing Logic
When logic is not found in primary pipelines, search by:
1. **Exact table names**: GlobalMRNxPacct, PatientAcctsXRefPermID, ClusteredAccts, PatientAcctCommercialHelpers
2. **Field names**: globalmrnifk, permid, demographicsHashString, isBacklogFlag
3. **Partial names**: clustered, commercial, backlog, encrypt
4. **Business terms**: GMRN, PermID, EDI, submitter, partner
5. **Patterns**: encrypt_aes, string_to_hex, block_compressed, lookup

### 5. Match Status Guidelines
- ✅ **Exact Match**: Same tables, same logic, same fields, same conditions
- ⚠️ **Equivalent**: Different implementation (SQL vs PySpark) but produces same business result
- ⚠️ **Partially Implemented**: Some aspects present, critical pieces missing
- ❌ **Missing**: Not found in any of the 5 primary pipelines (after thorough search)
- 🔍 **Found Elsewhere**: Located in different pipeline or notebook (specify exact location)

### 6. Severity Guidelines
- **Critical**: Missing business logic, data correctness at risk, compliance issues, encryption/security
- **High**: Implementation differences requiring validation, potential moderate data impact
- **Medium**: Different approaches likely correct but need confirmation, low data impact risk
- **Low**: Minor differences, exact matches, no data impact
